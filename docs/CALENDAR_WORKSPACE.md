# Authenticated calendar workspace

The console agenda reads the calendar manager's configured default scope and revision. It never accepts a scope, user, channel, owner, or guild identity from a request. `CONSOLE_ACTOR_USER_ID` maps every authenticated console credential to one explicit domain actor. `CONSOLE_ACTOR_CHANNEL_ID` is a trusted server-side audience value (default `console`); approved-group calendar access works only when that exact value is among the scope's configured channel IDs. A private scope requires the configured actor to be its owner. The calendar workspace stays disabled when the actor ID, manager, or authorized scope is unavailable.

The console API key is a shared credential with the authority of the configured actor. Cloudflare Access email or token identity never becomes the calendar actor. API-key clients use a valid `X-API-Key` header as an explicit API authentication path. Browser-session writes require a valid `console_session`, an exact `Origin` equal to `CONSOLE_TRUSTED_ORIGIN` (scheme, host, and optional port), and the session-bound `X-CSRF-Token` returned by `GET /api/calendar/items`. The trusted origin must be configured explicitly; request `Host` and forwarded headers do not define it. Cloudflare-authenticated requests can read the agenda, while writes require the separate API-key path unless they also have a valid console session.

`GET /api/calendar/items` returns only the authorized default scope, item IDs, a storage revision, safe agenda fields, sync state, and conflict operation IDs. Preview/apply bodies are strict JSON objects with bounded request size and exact allowed keys. Create previews are short-lived, single-use, actor/scope/revision-bound console proposals validated with the calendar time model. Edit, complete, delete, and conflict choices use `CalendarManager` preview and apply methods. Apply rechecks actor access and revision; manager tokens are actor-bound and single-use. Sync conflict choices also recheck the remote ETag before applying. Stale, revoked, malformed, cross-origin, and replayed operations fail closed.

The demo route is read-only. Browser rendering uses text nodes for all agenda content. The workspace supports keyboard-operable forms and actions, narrow layouts, filtered agenda, loading/error/empty states, sync-pending indicators, preview confirmation, conflict choices, and focus return after apply.
